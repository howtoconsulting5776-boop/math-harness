# Math Tutor — 초중고 수학 교육 오케스트레이터

수학 교육 작업을 **풀이 생성 → 독립 검산 → 눈높이 설명**의 생성-검증 팀으로 조율한다. 핵심 가치는 **정확성 보장**(검산을 거치지 않은 풀이는 학생에게 가지 않는다)과 **학년 적합성**이다.

> **실행 모드: 하이브리드.** 단일 문제·오답·개념·도형 = 에이전트 팀(생성-검증). 문제세트(학습지) = 서브 에이전트 팬아웃.

## 팀 구성
| 에이전트 | 역할 | 타입 |
|---|---|---|
| math-solver | 단계별 풀이 생성, 개념 설명 | opus |
| math-verifier | Python+SymPy 독립 검산 | general-purpose |
| math-explainer | 눈높이 설명, 오답 진단·교정 | opus |
| math-geometer | 도형 작도·출제·좌표 풀이 | general-purpose |

모든 Agent 호출은 `model: "opus"`.

## Phase 0 — 컨텍스트 확인 (초기/후속/부분 재실행)
1. 후속 신호("다시 / 수정 / 보완 / 난이도 바꿔 / 이 문제만 / 아까 그거")가 있고 직전 산출물(`_workspace/`)이 있으면 → **부분 재실행**(해당 에이전트만, 이전 결과를 입력으로).
2. 새 입력이면 → 초기 실행(기존 `_workspace/`는 `_workspace_prev/`로 이동).
3. 직전 대화에서 학년·모드가 고정돼 있으면 재확인 없이 이어간다.

## Phase 1 — 모드 판별
요청을 아래 모드로 분류한다. 학년이 없으면 문제 난이도로 추정하되 가정을 명시(모호하면 1회 확인).

| 모드 | 트리거(예) | 흐름 |
|---|---|---|
| **단일 풀이** | "이 문제 풀어줘", 사진 1문제 | 팀: solver→verifier→explainer |
| **개념 설명** | "○○ 개념 설명", "왜 이렇게 돼?" | 팀: solver(개념)→verifier(예제 검산)→explainer |
| **오답 분석** | "애가 이렇게 틀렸어", 학생 풀이 첨부 | 팀: solver(정답경로)→verifier→explainer(오개념 진단) |
| **도형** | "도형 그려줘", "기하 문제 풀어/출제" | 팀: geometer 주도 + verifier 교차검산 + explainer |
| **문제세트** | "학습지 풀어/해설", 여러 문제 | 팬아웃: 문제별 solver+verifier 병렬 → 취합 |

이미지 입력이면 먼저 Read로 문제를 추출(도형 포함 시 geometer).

## Phase 2 — 디스패치

### 2A. 팀 모드 (단일/개념/오답/도형)
1. `TeamCreate`로 팀 구성(필요 에이전트만 — 비도형은 geometer 제외 가능).
2. `TaskCreate`로 작업·의존성 등록: 풀이 → 검산 → 설명(도형은 작도·좌표 풀이를 선행).
3. 팀원이 `SendMessage`로 자체 조율(검산 FAIL ↔ 풀이 수정 루프, 최대 2회 재시도).
4. **종료 조건:** verifier PASS. 그 후 explainer가 최종 설명 생성.
5. 결과 종합 후 `TeamDelete`.

생성-검증 루프(핵심):
```
solver(풀이) → verifier(독립 재계산)
   ├ PASS → explainer(눈높이 설명) → 완료
   └ FAIL → solver에 구체적 수정점 전달 → 재풀이 (최대 2회)
```

### 2B. 팬아웃 모드 (문제세트)
1. 세트를 문제 단위로 분해(이미지면 문제별로 분리 인식).
2. 각 문제를 `Agent(math-solver, run_in_background=true)` + 직후 `Agent(math-verifier)`로 병렬 처리(문제 간 독립).
3. 도형 문제는 해당 항목만 geometer로.
4. 모든 결과 수집 → 검산 통과분만 해설지로 취합(미통과는 "확인 필요"로 표시, 누락 명시).
5. 채점 요청이면 학생 답과 대조표 생성.

> 팀 모드는 `TeamCreate` 1팀/세션 제약을 받는다. 팬아웃은 서브 에이전트라 제약 없음. 세트가 크면 팬아웃이 적합.

## 데이터 전달
- **태스크 기반**(팀 조율) + **메시지 기반**(검산 피드백) + **파일 기반**(산출물).
- 작업 파일: `_workspace/<id>_solution.md`, `_workspace/<id>_verify/`, `_workspace/<id>_figure.svg`.
- 팬아웃은 **반환값 기반**(서브 결과 수집) + 파일 기반.
- 산출물 저장 위치는 사용자가 지정하면 그 경로, 없으면 대화로 답하고 `_workspace/`에 보존(요청 시 노트로 정리).

## 에러 핸들링
| 상황 | 전략 |
|---|---|
| 문제 판독 불가 | 추측 금지. 안 보이는 부분 보고 + 1회 확인 |
| 검산 FAIL 2회 소진 | 해당 풀이 "미확정"으로 표시, 가능한 부분만 제공, 누락 명시 |
| Python/sympy 미설치 | verifier가 손계산 재유도로 폴백(하드스톱 금지), setup 안내 |
| 학년 모호 | 추정 + 가정 명시, 필요 시 1회 확인 |
| 문제 오류 의심(조건 모순) | 그대로 풀지 말고 모순 지점 보고 |
| 상충 데이터 | 삭제 금지, 출처 병기 |

## Phase 3 — 마무리
1. 결과 요약(모드, 학년, 핵심 답, 산출물 경로/그림).
2. 검산 상태 명시(PASS/미확정).
3. 후속 제안(연습 문제·유사 변형·노트 저장)을 가볍게.

## 테스트 시나리오
- **정상(단일):** "중2 일차함수 문제 풀어줘" → 모드=단일 → 팀(solver→verifier PASS→explainer) → 단계 풀이+눈높이 설명+연습.
- **정상(도형):** "직각삼각형 빗변 구하는 문제 그려서 풀어줘" → 모드=도형 → geometer 작도(SVG)+좌표풀이 → verifier 교차검산 → explainer 합성풀이 설명.
- **오답:** "우리 애가 -2x<6을 x<-3이라 했어" → 모드=오답 → solver 정답경로 → verifier → explainer(부등호 방향 오개념 진단·교정).
- **에러:** 사진이 흐려 분모가 안 보임 → 판독 불가 보고 + 어느 부분인지 확인 요청(추측 금지).
- **후속:** "방금 그 문제 더 쉽게 설명해줘" → Phase 0(후속+산출물 존재) → explainer만 부분 재실행.
