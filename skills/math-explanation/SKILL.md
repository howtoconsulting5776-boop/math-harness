# Math Explanation — 눈높이 설명·오답분석 규약

설명의 목표는 정답 전달이 아니라 **학생이 스스로 다시 풀 수 있게 되는 것**이다. 입력 풀이는 이미 math-verifier가 PASS한 정확한 풀이이므로, 여기서는 정확성이 아니라 **이해 가능성**만 책임진다. 단, 설명을 쉽게 하려고 수학적 내용을 바꾸지는 않는다.

## 1. 학년별 톤·어휘
| 학교급 | 어휘·표현 | 설명 전략 |
|---|---|---|
| 초등 | 일상어, 짧은 문장, 그림·수직선·구체물 | "만약 사탕이 12개 있고…" 식 이야기, 추상기호 최소화 |
| 중등 | 문자식 도입, 용어를 처음 쓸 때 한 번 풀어줌 | "왜 이 식이 성립하나"를 직관과 함께, 절차의 의미 강조 |
| 고등 | 형식적 표기 허용, 일반화·조건 강조 | 정의역·예외·일반성, 다른 단원과의 연결 |

어려운 용어는 **처음 등장할 때** 쉬운 말로 한 번 푼다. 초등에게 "정의역", 중등에게 과한 형식기호는 쓰지 않는다.

## 2. 스캐폴딩 — 떠먹이지 않기
각 단계에서 답을 바로 주지 말고 **발문**으로 사고를 유도한다:
- "여기서 양변에 같은 수를 더하면 무엇이 사라질까?"
- "이 도형에서 우리가 이미 아는 건 뭐지? 모르는 건?"
단계 끝에 "스스로 해보기" 한 줄을 남겨, 학생이 멈춰 생각하게 한다. 그 다음에 풀이를 잇는다.

## 3. 비유 사용 원칙
추상 개념은 구체적 비유로 직관을 만든다(저울=방정식, 레시피 배율=비례, 피자조각=분수). 단, **비유의 한계를 반드시 한 줄로 짚는다** — 틀린 직관이 굳는 것을 막는다(예: "저울 비유는 음수 양변엔 안 맞아").

## 4. 오답 분석 모드 (학생의 틀린 답·풀이가 주어질 때)
순서: **공감 → 진단 → 교정 → 재시도 제안.**
1. **공감/재현:** 학생이 *왜 그렇게 생각했는지* 그 논리를 먼저 복원한다("아마 이렇게 봤을 거예요").
2. **진단:** 오개념 유형을 짚는다(아래 분류).
3. **교정:** 그 오개념을 정확히 겨냥해 바로잡는다. 전체를 다시 풀지 말고 갈라진 지점부터.
4. **재시도:** 같은 함정을 피하는지 확인할 유사 문제 1개.

흔한 오개념 유형(체크리스트):
- **부호 오류** — 이항 시 부호, 음수 분배, 부등식 양변에 음수 곱할 때 방향.
- **분배/약분 오류** — `a(b+c)`, 분수 약분에서 항 단위 무시.
- **개념 혼동** — 넓이↔둘레, 반지름↔지름, 평균↔중앙값, 확률↔경우의 수.
- **과잉일반화** — `(a+b)^2 = a^2+b^2` 류, 규칙을 범위 밖에 적용.
- **절차 암기 실패** — 순서·조건을 빠뜨림(근의 공식 판별식, 정의역 확인).
- **문제 오독** — 묻는 것을 잘못 읽음(구하는 값 ≠ 구한 값).

> 더 많은 오개념 사례·교정 스크립트는 `references/misconceptions.md` 참조.

## 5. 다음 단계
설명 끝에: **핵심 한 줄 정리** + **연습 문제 1~2개**(난이도 같음/한 단계 위) + **개념 연결**(이 개념의 선수·후속).

## 출력 형식
```
## 이렇게 생각해요 (눈높이 설명)
1. [단계] — [왜] / 💭 [발문]
...
## (오답이 있으면) 어디서 갈라졌나
- 네 생각: ... / 바로잡기: ...
## 한 줄 정리
## 더 해보기
- 연습: ...  | 연결 개념: ...
```
